Architecture

How It Works

~/Projects/myapp (bind mount)
🚫 ~/.ssh, ~/.aws NOT mounted
➡️
SSH tunnel
📦 DEV CONTAINER
Claude Code + tools
Non-root user: developer
Egress firewall (default-deny)
Managed settings (enforced)
/workspace (only writable dir)
Security Model

Defence in Depth — 5 Layers

L1
Filesystem Sandboxing
Only /workspace is bind-mounted. Claude cannot touch host system files, other projects, or home configs
L2
Non-Root Execution
remoteUser: "developer" — Claude Code rejects --dangerously-skip-permissions when run as root
L3
Network Egress Firewall
Default-deny iptables. Only api.anthropic.com, GitHub, package registries — prevents data exfiltration
L4
Managed Settings (Highest Precedence)
/etc/claude-code/managed-settings.json overrides ALL user settings. Deny .env*, *.pem, credentials
L5
Secret Hygiene
Never mount ~/.ssh, ~/.aws. Use SSH agent forwarding or repo-scoped tokens instead
Even with --dangerously-skip-permissions, the blast radius is limited to the container + workspace bind mount

Key security config
// devcontainer.json
"remoteUser": "developer",
"workspaceMount": "...target=/workspace,type=bind",

// Dockerfile
COPY managed-settings.json /etc/claude-code/

// managed-settings.json
"deny": ["Read(.env*)", "Read(*.pem)"],

// init-firewall.sh
iptables -P OUTPUT DROP
iptables -A OUTPUT -m set
  --match-set allowed-domains dst -j ACCEPT
Commit once → every engineer gets identical tools, conventions, and security policy

Eyes Open

Costs, Risks & Tradeoffs

COSTS
Docker Desktop licensing — paid seats for commercial use, or switch to Podman / Rancher Desktop (free)
Image maintenance — someone owns keeping the base image current (toolchain updates, security patches)
Setup engineering — ~1–2 days to build & test the first container per repo
RISKS
Adoption resistance — some engineers prefer bare metal; forcing migration creates friction
Rebuild latency — Dockerfile changes trigger full image rebuilds (minutes, not seconds)
I/O on macOS — bind-mounted volumes can be slower than native filesystem for large node_modules
MITIGATIONS
Hybrid rollout — container optional at first; make it the better path, not a mandate
Pre-built images — push cached images to registry; devs pull, not build
Named volumes — use Docker named volumes for node_modules + VirtioFS for near-native I/O
